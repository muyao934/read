区块链诈骗与骗局

总览　/　2024 年　/　钓鱼与授权盗币

5,547 万 DAI 签名钓鱼

2024 年 8 月 20 日，一名以太坊用户在冒充 DeFi Saver 的钓鱼网站上签了一笔交易，把自己的 DSProxy 合约钱包的所有权交给了骗子。这个 DSProxy 控制着他在 Maker 协议里的一个金库，骗子随即从中提走约 5,547 万枚 DAI，约值 5,500 万美元。ScamSniffer 把它记为 2024 年钱包盗币类钓鱼里最大的一笔。到 2026 年 11 月，没有查到刑事起诉；受害者追到的一部分赃款冻结在 Coinbase，正在旧金山联邦法院打民事官司。

概要

这一案和常见的授权钓鱼不同，区别在受害者签出去的权限。普通的 approve 或 Permit 只让对方转走某一种代币，额度可以设上限，事后也能撤销，这类签名见 Inferno Drainer。本案受害者签的是 DSProxy 合约的 setOwner，换掉的是整个合约钱包的主人[5][1]。他的 Maker 金库由这个 DSProxy 控制，谁当 DSProxy 的主人，谁就能操作金库。签完以后，受害者自己再调用 DSProxy 就失败了[1][2]。

2024 年 8 月 20 日是星期二。据 The Block 和 Decrypt，链上调查者 ZachXBT 最先发现这起事件[1][7]；Lookonchain、CertiK、BlockSec 随后给出分析[1][2]。按 BlockSec 的说法，受害者被引去签了一笔更换金库主人的交易，骗子再发一笔交易把金库掏空[1]。被提走的 DAI 约 5,547 万枚[1][2]。Lookonchain 称骗子很快把其中 2,750 万枚换成了 10,625 枚 ETH[2]。CertiK 认为骗子用的是 Inferno Drainer 的工具[1]，受害者后来的起诉书也这样说[10]。

ScamSniffer 的 2024 年报统计，钱包盗币工具全年造成约 4.94 亿美元损失，最大单笔 5,548 万美元，就是这一起[5]。受害者报了警，又雇私人公司追踪；2024 年 12 月，Coinbase 冻结了追到其平台一个散户账户里的一部分赃款[10]。2026 年 5 月，受害者起诉 Coinbase 要回这笔钱；Coinbase 请求把钱提存到法院后退出，听证定在 2027 年 1 月 22 日[12][13]。到 2026 年 11 月，没有查到针对骗子的刑事起诉、逮捕或制裁的公开报道。

背景

Maker 金库和 DSProxy

Maker 金库是一种抵押债务仓位：用户存入抵押品，借出和美元挂钩的稳定币 DAI[1]。很多用户不直接操作金库合约，而是先给自己部署一个 DSProxy。DSProxy 由 dapphub 编写，源码注释说，它让用户用一个固定的身份执行一连串原子操作，“因为代理的主人可以更换”，所以也能用于多签这类所有权安排[15]。Maker 的金库管理合约 DssCdpManager 给每个金库登记一个主人[16]，通过 DSProxy 开的金库，登记的主人就是 DSProxy 的地址。

据 CertiK 和 BlockSec 的分析，本案受害者的普通钱包地址（EOA）是一个 DSProxy 的主人，这个 DSProxy 控制着一个 Maker 金库[1]。

DeFi Saver

DeFi Saver 是管理 Maker、Aave 等协议仓位的工具，起诉书称它是“非托管”的，资产仍在用户自己的合约里[10]。受害者在起诉书里说，他用 DeFi Saver 管理以 DAI 计的资产，用笔记本电脑上的硬件钱包签名[10]。SlowMist 的 8 月报告把这一案描述为针对受害者“DeFi Saver Proxy”的钓鱼[3]。各方报道都没有说 DeFi Saver 本身被攻破，本站也没有找到 DeFi Saver 的公开声明。

Inferno Drainer 回来了

Inferno Drainer 2023 年 11 月宣布关闭，2024 年又活跃起来。据 ScamSniffer 的年报，Pink Drainer 5 月底退出时占 28% 的份额，被 Inferno 吸收；10 月底 Angel 宣布接管 Inferno 之后，Inferno 仍占 40% 到 45%[5]。Cointelegraph 引安全公司 Blockaid 的数据说，2024 年用 Inferno 搭建的恶意应用从年初约 800 个增加到年底 2,400 多个[8]。工具包怎样出租、怎样分账，见 Inferno Drainer。CertiK 认为本案用的就是它[1]。起诉书把 Inferno 称作一个持续运作的犯罪团伙，原告据此对匿名被告提出 RICO 索赔[9][10]。

为什么算诈骗

本站按转账是谁签的来分：受害者自己签的交易算诈骗。本案受害者的私钥没有泄露，交易是他在假网站上自己签的。BlockSec 的分析师 Jingyi Guo 对 The Block 说，从链上数据看，受害者签了钓鱼交易的可能性大于私钥泄露[1]。CertiK 和起诉书都用了“进入账户”“取得访问权”这类说法[1][10]，说的是签名之后的结果：骗子拿到的是 DSProxy 的主人身份，私钥仍在受害者手里。

骗术怎样运作

本案的关键是一条所有权链：受害者的钱包是 DSProxy 的主人，DSProxy 是 Maker 金库登记的主人，金库里是抵押品和 DAI[1][16]。骗子不需要私钥，也不需要任何代币授权，只要把链上的第一环换成自己。

setOwner 换掉的是什么

DSProxy 继承自 dapphub 的 DSAuth 合约。DSAuth 只记一个主人 owner，带 auth 修饰的函数只有主人、合约自己或主人指定的权限合约能调用。setOwner 本身也带 auth，主人可以把 owner 改成任何地址[14]：

// dapphub/ds-auth，src/auth.sol，commit a51e7ca（节选）
function setOwner(address owner_) public auth {
    owner = owner_;              // 一个参数，直接换主人
    emit LogSetOwner(owner);
}

modifier auth {
    require(isAuthorized(msg.sender, msg.sig), "ds-auth-unauthorized");
    _;
}

function isAuthorized(address src, bytes4 sig) internal view returns (bool) {
    if (src == address(this)) {
        return true;
    } else if (src == owner) {   // 只认当前主人
        return true;
    } else if (authority == DSAuthority(address(0))) {
        return false;            // 没设权限合约，其他人一律拒绝
    } else {
        return authority.canCall(src, address(this), sig);
    }
}

出处：dapphub/ds-auth，commit a51e7ca（2021-07-29），src/auth.sol，节选，函数声明合并为一行[14]。中文注释为本站所加。

DSProxy 最要紧的函数 execute 也带 auth。主人可以让它用 delegatecall 执行任意一段合约代码，这段代码以 DSProxy 的身份运行，能动用 DSProxy 名下的一切[15]：

// dapphub/ds-proxy，src/proxy.sol，commit 20a0e4b（节选）
function execute(address _target, bytes memory _data)
    public auth note payable returns (bytes memory response)
{
    require(_target != address(0), "ds-proxy-target-address-required");
    // 在 DSProxy 自己的上下文里执行 _target 的代码
    assembly {
        let succeeded := delegatecall(sub(gas, 5000), _target, add(_data, 0x20), mload(_data), 0, 0)
        ...
    }
}

出处：dapphub/ds-proxy，commit 20a0e4b（2022-06-05），src/proxy.sol，节选，省略号为本站所加[15]。

Maker 的 DssCdpManager 在每个金库操作前检查调用者：必须是金库登记的主人 owns[cdp]，或者被这个主人授权过[16]。调整抵押和债务的 frob、转出抵押品的 flux、转出 DAI 的 move 都要过这道检查：

// makerdao/dss-cdp-manager，src/DssCdpManager.sol，commit 95eb088（节选）
mapping (uint => address) public owns;      // CDPId => Owner

modifier cdpAllowed(uint cdp) {
    require(msg.sender == owns[cdp] || cdpCan[owns[cdp]][cdp][msg.sender] == 1, "cdp-not-allowed");
    _;
}

出处：makerdao/dss-cdp-manager，commit 95eb088，src/DssCdpManager.sol，节选，修饰符参数合并为一行[16]。

三段合起来看：金库登记在 DSProxy 名下，谁能让 DSProxy 执行代码，谁就能操作金库。setOwner 之后，这个人成了骗子。受害者的地址再也通不过 auth，这就是他当天的补救交易失败的原因[1][14]。

和普通代币授权的区别

approve、Permit 等代币授权DSProxy 的 setOwner
交出的是什么转走某一种代币的额度整个合约钱包的主人身份[14]
范围一种代币，额度可以设上限DSProxy 名下的所有仓位和资产，没有上限[15]
能不能撤回受害者自己把额度改成 0受害者已通不过 auth，只有新主人能再改[14]
钱包看到的代币名、授权对象，常有额度一个地址参数，没有代币和金额[14]
签的是不是 setOwner

ScamSniffer 的年报明确写的是针对 Proxy 所有权地址的 setOwner 签名[5]。CertiK 对 The Block 说，骗子用受害者的 EOA 转移了 DSProxy 的所有权；BlockSec 说受害者被骗签了一笔“更换金库主人”的交易[1]。起诉书没有点函数名，只说受害者被骗“授权了一个恶意的代理钱包或智能合约权限”，把实际控制权交给了骗子[10]。几方说的是同一件事，本站按 ScamSniffer 和 BlockSec 的说法写。

钱包为什么看不出危险

  • 网站像真的。假页面模仿 DeFi Saver 的登录页，只把 .com 换成了 .app[10]。受害者以为自己在登录[7]。
  • 调用的是自己的合约。setOwner 发往受害者自己用过的 DSProxy，收款方不是陌生地址，按地址拦截的黑名单派不上用场。
  • 没有资产变化。这笔交易本身不转出任何代币，钱包按余额变化做的模拟只会显示没有变化。ScamSniffer 把“欺骗钱包的模拟结果”列为 drainer 绕过检测的手法之一[5]。
  • 参数只是一个地址。setOwner 只有一个参数[14]，界面上是一串十六进制字符，看不出它会让出金库。
  • 硬件钱包不管签什么。受害者用的是硬件钱包[10]，它保护的是私钥，签什么内容仍由人决定。
“铸出”还是“提走”

The Block 写，骗子把主人改成自己后，“铸出了 55,473,618 枚 DAI”[1]。Cointelegraph 写的是这笔签名改变了 Maker 里 5,547 万枚 DAI 的所有权，骗子随后把钱提走[2]；BlockSec 的说法是“掏空了金库”[1]。前一种说法意味着骗子用金库的抵押借出新的 DAI，后一种像是金库里本来就有 DAI。公开报道没有说明金库的抵押品和债务，起诉书里的金额也被涂黑[10]，本站不推断，两种说法并列。

经过

8 月 20 日：签名和提款

起诉书称，骗子用一个链接把受害者引到假的 DeFi Saver 登录页，域名以 .app 结尾，真的以 .com 结尾[10]。受害者在页面上签了名。按 BlockSec 对链上数据的解读，这笔交易把 DSProxy 的所有权交给了 Etherscan 标为 Fake_Phishing187019 的地址；所有权随后又转到另一个地址，由它负责提款和后面的洗钱[1]。Lookonchain 称，骗子已把所有权设到一个新建的地址，并从协议里提走了资产[2]。

受害者似乎很快发现了问题。Cointelegraph 写道，他想把钱提到一个新地址，交易失败了，因为主人已经换了[2]。BlockSec 的 Jingyi Guo 说，受害者试图调用 DSProxy，但他已不是 DSProxy 的主人，调用失败[1]。

谁先发现

各家说法不一。The Block 和 Decrypt 都说链上调查者 ZachXBT 最先发现[1][7]。Cointelegraph 当天的报道引的是 Lookonchain[2]。8 月 21 日，SlowMist 旗下的 MistTrack 发布了资金追踪[3]，CertiK 和 BlockSec 向 The Block 解释了作案过程[1]。ScamSniffer 是在 9 月的月度统计和年报里记录这一案的[4][5]，本站没有找到它最先发现的依据。

一起占了 8 月的近九成

据 ScamSniffer 9 月 3 日的统计，8 月约 9,145 名受害者因钓鱼损失约 6,300 万美元，人数比 7 月少 34%，金额却涨了 215%；Cointelegraph 算出，这一起占当月被盗金额的 88%[4]。同一篇报道的导语写的是 8 月损失 6,600 多万美元[4]，两个数字出自同一篇，没有说明差别。放大到全部安全事件，SlowMist 统计 8 月全行业损失约 3.16 亿美元，只追回约 1,358 万美元；同月还有一笔约 4,064 枚 BTC 的可疑转账，ZachXBT 说其中只有约 20.5 万美元被还回[3]。

追踪和起诉

受害者报了警，又雇了 Zero Shadow 和 Five Stones Intelligence 两家公司追踪赃款[10]。2024 年 11 月 30 日，Zero Shadow 通知 Coinbase，部分赃款进了 Coinbase 的一个地址；12 月 2 日，Coinbase 确认地址属于一个散户账户，钱还在，并采取了防止转走的措施[10]。Coinbase 要求先有法院判定归属才放款[10]。一年五个月后，受害者在 2026 年 5 月 4 日起诉[9]。

起诉书里的金额被涂黑，Decrypt 说它描述的经过和 2024 年 8 月这一案“非常相似”[7]，Cointelegraph 则直接写成本案[8]。

钱去了哪里

当天换成 ETH

Lookonchain 称，骗子把 2,750 万枚 DAI 换成了 10,625 枚 ETH[2]。按 MistTrack 8 月 21 日的追踪，约 5,500 万枚 DAI 先分到多个地址，一部分又归集到一个地址，多数随后换成 ETH；当时其中一个地址还持有 6,745.88 枚 ETH 和约 1,927 万枚 DAI[3]。地址投毒那一案里，被骗的 WBTC 当天也被换成了 ETH，见地址投毒骗走 1,155 枚 WBTC。各方报道都没有提到有人冻结这批 DAI。

混币和交易所

按原告和 Coinbase 的联合案件管理陈述，赃款经 CowSwap、Tornado Cash 等非托管工具转手，用来切断存入和取出地址之间的联系[11]。Cointelegraph 据起诉书写道，骗子经 Tornado Cash 洗过以后，把一部分“可追溯的赃款”存进了一个 Coinbase 散户账户[8]。

起诉书称，Zero Shadow 和 Five Stones 找到证据，显示一名可能是乌克兰籍的人可能在洗钱中起了重要作用[10]。这是原告一方的说法，Coinbase 答辩时表示不知情；此人没有被起诉，本站不写他的名字。

追到并冻结在 Coinbase 的金额，起诉书里涂黑了[10]，公开报道也没有给出数字。其余赃款的去向，公开资料里没有进一步的说明。

受害者与规模

本案

本案只有一名受害者。法院文件用姓名缩写称呼他，起诉书说他用笔记本电脑上的硬件钱包签名、用 DeFi Saver 管理以 DAI 计的资产[10]，Decrypt 称他为“巨鲸”[7]。他的身份没有公开，本站也不写其他能认出他的细节。

“最大的一笔”按什么口径

ScamSniffer 统计的是钱包盗币工具（wallet drainer）造成的钓鱼损失。按它的年报，单笔最大的被盗金额 2023 年是 2,405 万美元，2024 年是本案的 5,548 万美元，2025 年降到 650 万美元[5][6]。这个“最大”只在这一口径里成立。转错地址的地址投毒、被骗说出助记词的社工案不在 ScamSniffer 的统计里，金额更大的案子另有，例如地址投毒骗走 1,155 枚 WBTC，约 6,800 万美元。

放在 2024 年的钓鱼损失里

ScamSniffer 统计，2024 年钱包盗币类钓鱼共造成约 4.94 亿美元损失，受害地址约 33.2 万个；损失超过 100 万美元的大案 30 起，合计约 1.71 亿美元。8 月和 9 月分别出现 5,548 万和 3,251 万美元的大案，两个月占全年大案损失的 52%[5]。按签名类型分，大案损失里 Permit 占 56.7%，setOwner 占 31.9%[5]。本站按这两个数推算，31.9% 约合 5,455 万美元，和本案差不多，2024 年大案里的 setOwner 损失基本就是这一起。ScamSniffer 2025 年的对比表把 2024 年的主要签名类型写成“Permit/setOwner”[6]。

追查与执法

到 2026 年 11 月，本站没有查到针对本案骗子的刑事起诉、逮捕、制裁或执法扣押的公开报道。起诉书说受害者报了警[10]，没有说是哪个机构，也没有执法机构公开说过在查这一案。骗子和 Inferno Drainer 开发者的身份都没有公开。

民事诉讼

2026 年 5 月 4 日，受害者在北加州联邦地区法院起诉 Coinbase 的两家公司和一名匿名被告，案号 3:26-cv-04050[9]。对匿名被告，他依据《计算机欺诈和滥用法》和反诈骗的 RICO 条款索赔，要求三倍赔偿；对 Coinbase，他请求法院确认冻结的币归他所有，并命令 Coinbase 交还[9]。起诉书部分内容获准密封[11]。

Coinbase 在 7 月 20 日的答辩里承认了冻结的经过和账户的存在，对盗币经过表示不知情；它说自己对这笔钱没有利益，请法院让原告和账户持有人当面争归属[10]。经法院许可的早期取证，Coinbase 查明了账户持有人，法院准许以化名起诉他[11]。持有人 9 月 3 日经电子邮件收到送达，没有答辩，10 月 7 日被登记缺席[12][13]。

10 月 1 日，Coinbase 请求把争议资金存入法院后退出诉讼，原告不反对[12]。原告预计申请简易判决，确认这笔钱归他[11]。案件 10 月 13 日改派 Charles R. Breyer 法官，提存动议的听证定在 2027 年 1 月 22 日[13]。到 2026 年 11 月，法院还没有判定这笔钱的归属，冻结的币仍在 Coinbase。

冻结以后为什么还要打官司

Cointelegraph 指出，交易所收到警报后常会冻结可疑资金，但多半要先有法院命令才肯把钱交给自称失主的人[8]。本案从冻结到起诉过了一年五个月，起诉到听证又排了八个多月[10][13]。

怎样识别

签名之前
  • 核对完整域名，从书签进入常用工具。本案假页面和 DeFi Saver 的登录页长得一样，只是 .com 换成了 .app[10]。
  • 看清调用的函数名。带 Owner、Authority 字样的调用，例如 setOwner、setAuthority，换的是合约的控制人[14]。登录、验证、领取都不需要换主人，看到这类请求就停下。
  • “没有资产变化”不等于安全。本案这笔签名不转出任何代币[14]，按余额变化的模拟看不出问题，ScamSniffer 也说 drainer 在研究怎样欺骗钱包的模拟[5]。
用合约钱包的人
  • 弄清自己的仓位登记在谁名下。仓位挂在 DSProxy 这类合约钱包下面时，合约钱包的主人就是全部仓位的主人[15][16]，丢掉主人身份就丢掉一切。
  • 撤销授权的办法救不了这种签名。代币授权可以自己改成 0，主人换掉以后，原主人连改回来的权限都没有[14]。本案受害者当天就发现了，补救交易仍然失败[1]。
  • 大额仓位分开放，用多签或另设一个只用来签管理操作的地址，日常浏览用的地址不连这个钱包。
  • 硬件钱包只保护私钥。本案受害者用的就是硬件钱包[10]。
已经签了
  • 尽快报警，找链上追踪公司，并通知赃款可能流入的交易所。本案的部分赃款三个多月后进了 Coinbase，被冻结[10]。
  • 冻结只是第一步。交易所多半要法院命令才放款[8]，本案到 2026 年 11 月仍在诉讼中[13]。
