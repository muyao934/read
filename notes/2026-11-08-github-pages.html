用 GitHub Pages 发布静态网页

把仓库里的 HTML 文件原样放到一个网址上，手机、电脑随时打开。免费、不用服务器，但有几处和本地双击打开不一样。

一句话

免费账户只能从公开仓库发布，发布出去的网站任何人都能看到；网址是 https://用户名.github.io/仓库名/，保存设置后要等一两分钟才能打开。

它是什么

GitHub Pages 把仓库某个分支里的文件当成网站发布。纯 HTML、CSS、JS 的站点不需要任何构建，推上去就是网页。在仓库里直接点开一个 .html 文件，GitHub 只显示源码；要看渲染后的页面，得开 Pages。.md 文件则在仓库页面里就能渲染。

  • git push推送到 main 分支
  • 自动部署GitHub Actions 跑一次 pages-build-deployment，约一两分钟
  • 上线用户名.github.io/仓库名/
账户能从哪种仓库发布网站谁能看
Free只能公开仓库所有人
Pro、Team公开或私有仓库仍是所有人
Enterprise Cloud公开或私有仓库可以限制为组织成员
仓库私有不等于网站私有只有 Enterprise Cloud 能给 Pages 加访问控制。其他情况下，只要开了 Pages，知道网址的人都能看。不要往里放公司内部资料、密钥、个人信息。

发布步骤

  1. 建仓库并推送在 GitHub 网页上建一个空的公开仓库，把本地文件夹推上去。首页要叫 index.html，放在根目录。
  2. 打开 Pages仓库 Settings → Pages，Source 选 “Deploy from a branch”，Branch 选 main，目录选 / (root)，保存。
  3. 等部署完成Actions 页能看到部署进度。完成之前访问网址是 GitHub 的 404 页“There isn't a GitHub Pages site here”，这是正常的。
  4. 以后更新每次 git push 都会自动重新部署，不用再改设置。

本地正常、上线出问题

本地双击打开走的是 file://，上线后是 https://，服务器也换成了 Linux。下面几种情况本地看不出来：

现象原因怎么办
某些页面 404macOS 不区分文件名大小写，Pages 区分。链接写 About.html、文件叫 about.html，本地能开，线上打不开文件名一律小写，链接照抄文件名
样式、图片全丢链接以 / 开头，指向的是 用户名.github.io/ 而不是 /仓库名/全部写相对路径，如 assets/a.css、../index.html
以下划线开头的文件 404Pages 默认先用 Jekyll 处理，Jekyll 会跳过 _ 开头的文件和目录在根目录放一个空文件 .nojekyll
改完推送，刷新还是旧的Pages 返回 cache-control: max-age=600，浏览器最多缓存 10 分钟等部署完成后强制刷新，或换隐身窗口

反过来也有：用 fetch() 读本地 JSON 的页面，双击打开会失败，上线后反而正常。想两边都能用，就把数据写成 data.js，用 <script> 加载。

一台电脑用两个 GitHub 账号

推送时 GitHub 认的是 SSH key，不看 git config user.name。默认的 git@github.com 只会用一把 key，所以第二个账号要在 ~/.ssh/config 里起一个别名，指定它自己的 key：

Host github-work
    HostName ssh.github.com
    Port 443                    # 走 443 端口，22 端口被封的网络也能用
    User git
    IdentityFile ~/.ssh/id_ed25519_work
    IdentitiesOnly yes          # 只用这把 key，不去试别的

然后远程地址把 github.com 换成别名，先测一下认的是哪个账号：

ssh -T git@github-work      # 应回复 Hi 账号名!
git remote set-url origin git@github-work:账号名/仓库名.git

推送身份：SSH key

决定有没有权限推送到这个仓库。key 不对会报 Permission denied (publickey)。

提交作者：user.name / user.email

写进每条提交，公开仓库里任何人都能看到，和推送用的账号无关。

别让邮箱跟着提交公开

提交里的邮箱推上去以后就留在历史里。不想公开真实邮箱，在仓库里单独设成 GitHub 给的 noreply 地址，只影响这个仓库：

git config user.name  "账号名"
git config user.email "数字ID+账号名@users.noreply.github.com"

noreply 地址在 GitHub 的 Settings → Emails 里能看到。同一页勾上 “Keep my email addresses private” 和 “Block command line pushes that expose my email”，以后用真实邮箱的提交会被拒绝推送。

已经推上去的怎么办只能改写提交历史再强制推送（git commit --amend --reset-author 加 git push --force）。强制推送会覆盖远程历史，别人已经拉过的副本里还留着旧邮箱。
