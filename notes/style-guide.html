版式样板

这一页把阅读库文章能用的组件各放一个例子。每篇文章的外壳和这一页一模一样，正文只从这里挑组件，所以新文章不用再调布局和字体。

一句话

外壳固定：顶栏、标题、导语、一句话结论、目录、翻页、页脚。颜色只有四种意思：红色是风险，琥珀色是注意，蓝色是推荐做法，绿色是成功。

文字

正文段落占满正文栏，和下面的表格、图右边对齐。加粗用来标关键词，命令和文件名写成 git push，链接写成 这样。

小标题

节里还要再分层时用小标题。列表用来列举并列的几项：

  • 无序列表：各项之间没有先后。
  • 每项尽量一句话说完。
  1. 有序列表：各项有先后。
  2. 步骤多、每步要解释时，改用下面的“步骤”。
引文：原话照录，下面写出处。出处，日期

提示框

补充灰色提示框：正文之外值得一提的细节。
推荐做法蓝色提示框：读完应该怎么做。
注意琥珀色提示框：容易误解、有条件、尚未确认的说法。
风险红色提示框：会丢数据、丢钱、泄露信息的操作。

流程和步骤

流程块：一件事经过的几个环节。宽屏横排，手机竖排，箭头自动转向。

  • 普通环节一两句说明
  • 推荐蓝色
  • 注意琥珀色
  • 出错红色
  • 成功绿色

步骤：要照着做的操作，每步一个加粗的短标题。

  1. 第一步的短标题这一步做什么、为什么。
  2. 第二步的短标题命令写成 git status。

表格

表格外面一律包 tbl-wrap：列多的表在手机上只在表格里横向滑动，整页不会左右晃。数字列右对齐。

对照

两样东西对比时用对照。宽屏并排，手机上下排，所以正文按卡片标题称呼它们，不说“左边”“右边”。

做法甲

优点和代价各一两句。

做法乙

优点和代价各一两句。

代码

命令和代码用代码块。注释是灰色，错误写法垫红底，正确写法垫绿底；太长的行在块里横向滑动。

git config user.email "you@example.com"   # 注释
git remote add origin git@github.com:name/repo.git
git remote add origin git@github-name:name/repo.git

代码说明：这段代码出自哪里、在什么环境下运行。
