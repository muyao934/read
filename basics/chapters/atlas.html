中心化 / 托管

中心化方案：信任一家机构

中心化方案没有链上证明：一家机构收下你的资产，再由它决定在另一条链上给你发多少。“证明者”就是这家机构本身。听起来最不“区块链”，但它简单、快、便宜，而且是 BTC 这类不能跑合约的链最常见的出路。实际交易量里，很大一部分跨链其实是这一类。

拆开看：WBTC 是怎么铸出来、怎么换回去的

WBTC 是最典型的托管包装币，它的合约是公开的（WrappedBTC/bitcoin-token-smart-contracts）。链上合约只做两件事：记录请求和检查谁有权确认。BTC 有没有真的到账，合约看不到，全靠托管方。

角色谁在 Factory 合约里能调用
商户（merchant）经过 KYC 的机构，用户通过它们直接铸造和赎回addMintRequest(amount, btcTxid, btcDepositAddress)、cancelMintRequest、burn(amount)
托管方（custodian）保管 BTC 的机构confirmMintRequest、rejectMintRequest、confirmBurnRequest(requestHash, btcTxid)，以及给每个商户设 BTC 充值地址
Controller 的 owner治理多签增减商户、更换托管方、更换 Factory、暂停

消息验证网络

“谁来证明”交给一个独立网络

这类协议只负责一件事：让目标链相信“源链上的某个合约发出了这条消息”。资产怎么锁、怎么铸，由建在上面的代币标准（OFT、NTT、ITS、Warp Route）决定。

LayerZero V2

应用自己挑验证者

验证：每个应用为每条路径配置一组 DVN（去中心化验证网络），格式是 X-of-Y-of-N：几个“必须”的 DVN 全部确认，再加上可选 DVN 里够数的确认。每个 DVN 独立检查消息的 payloadHash。

合约：EndpointV2 不可升级、无需许可，核心方法 quote / send / verify / lzReceive。验证通过后谁都能调用 lzReceive，Executor 只是代付 gas 的服务。

代币：OFT 新币用销毁 → 铸造；已有的币用 OFT Adapter 在原链锁定。USDT0 就是在以太坊上把 USDT 锁进 OFT Adapter，再到各链铸 USDT0。官方部署表 150+ 条链，含 BSC、Solana、Tron、Aptos、Sui，没有 Qtum。

Wormhole

19 个 Guardian，13 个签名

验证：19 个 Guardian 节点观察各条链，对消息签名，凑够 13 个就成为一份 VAA（可验证动作批准）。有些链由部分 Guardian 代为观察，但最终都是标准的 13-of-19 多签。每个发送方可以选等待的最终性程度（consistency level），等得越少越快，也越可能遇到重组。

代币：WTT（原 Token Bridge）锁定原币、在目标链发包装币；NTT 让发行方自己控制代币，源链可选“锁定模式”或“销毁模式”。

事故：2022-02 Solana 侧签名验证被绕过，损失约 3.26 亿美元。

Axelar

一条专门做跨链的 PoS 链

验证：Axelar 是一条 Cosmos SDK 链，它的验证者除了出块，还要投票确认各条外部链上的跨链请求，通过后由目标链的 Gateway 合约授权。

合约：源链调用 Gateway 的 callContract（带币用 callContractWithToken）；目标链应用继承 AxelarExecutable，在 _execute 里写业务逻辑，执行前通过 validateContractCall 确认已被批准，同一份批准不能用两次。

代币：Interchain Token Service（ITS）。新链接入可以走 Amplifier 提案流程。

Hyperlane

谁都能部署，验证模块可插拔

验证：每个应用可以用 Mailbox 的默认 ISM（链间安全模块），也可以指定自己的：多签、聚合多个模块、限额、暂停等。

合约：源链 Mailbox.dispatch；目标链 Mailbox.process 先调用 ism.verify(metadata, message)，通过后再调用接收合约的 handle。

代币：Warp Route：抵押 → 合成（源链锁、目标链铸）、原生币 → 合成、原生币 → 抵押。Qtum 不在官方 registry 里，但 Hyperlane 允许自行部署。

Chainlink CCIP

第 04 章展开

验证：CCIP 2.0（2026-09-28）里由 Cross-Chain Verifier 证明消息，默认是 16 个独立节点运营方组成的委员会；执行无需许可。

采用者：Ronin 已接入 CCIP（CCIP 官方目录有 Ronin 主网的 Router 和链选择器），官方桥迁移到 CCIP；Synthetix、Aave 早期接入。

Celer

cBridge + 消息总线

验证：各链上的 Message Bus 合约，配合一条基于 Tendermint 的中继链 State Guardian Network（SGN）。

规模：cBridge 支持 40+ 条链和 L2。

LayerZero 的 X-of-Y-of-N 是怎么工作的

流动性 / 意图

“意图”（intent）的意思是：用户只说“我在 A 链付 X，要在 B 链收到 Y”，由求解者或中继去想办法、先垫钱。用户几乎立刻到账，安全问题变成“垫付的人怎么可靠地拿回钱”。Across 已在生产环境支持 ERC-7683 意图标准。

Across

中继垫付 + UMA 乐观结算

源链 SpokePool depositV3 → 中继在目标链 SpokePool 调用 fillV3Relay 用自己的钱付给用户 → Dataworker 汇总一段时间内所有链的成交，向以太坊上的 HubPool 提交一个根包（root bundle）并押保证金 → 挑战期内没人用 UMA 发起争议，就最终确定，通过官方桥把还款指令发到各链。

deBridge DLN

“0-TVL”

不设共享流动性池，由互相竞争的求解者按需提供流动性，自称非托管、已处理 200 亿美元以上的跨链交易量，覆盖含 Solana 在内的 25+ 条链。

Stargate V2

建在 LayerZero 上的流动性池

以 LayerZero V2 为传输层，提供各链统一的原生资产流动性池（Hydra 机制、额度分配）；转账有单独发送的 Taxi 模式和拼车省钱的 Bus 模式。文档现已并入 LayerZero 文档。

THORChain

真·原生币互换

节点用门限签名（TSS）共同管理各条链上的金库，按默认每 20 个节点一片分片；验证者轮换（churn）时把资产迁到新金库。用户付 BTC，从 ETH 金库收到真正的 ETH，没有包装币。

聚合器（LI.FI / Jumper、Socket / Bungee、BNB Chain 官网的“桥”）自己不桥接，只帮你在上面这些路线里挑一条。BNB Chain 官方文档原话：“we do not operate the routes”。2024-01 Socket 的事故说明，聚合器合约上的无限授权本身就是风险。
