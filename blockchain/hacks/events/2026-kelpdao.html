区块链被盗事件编年史

总览　/　2026 年　/　十亿美元级失守与信任链

KelpDAO rsETH 跨链被盗

2026 年 4 月 18 日，一条伪造的跨链消息通过了 LayerZero 验证者的签字，KelpDAO 在以太坊上的桥合约放出 116,500 枚 rsETH，约 2.92 亿美元。这条路径只配置了一个验证者，攻击者让它读到了假数据。攻击者把 rsETH 押进 Aave 借走真实的 ETH，引发的坏账担忧让 DeFi 锁仓量两天内减少约 130 亿美元。

概要

rsETH 是 KelpDAO 发行的再质押代币，借助 LayerZero 的 OFT 标准扩展到约 20 条链。以太坊上的 rsETH 锁在 RSETH_OFTAdapter 合约里，远端链上铸出等量的副本；副本跨回以太坊时，适配器要等接收库确认“配置的验证者都签了字”才放币。Kelp 的 Unichain→以太坊路径只配置了一个验证者，即 LayerZero Labs 运营的 DVN[1][3]。

2026 年 4 月 18 日 17:35（UTC），一条声称来自 Unichain 的消息得到了这个验证者的签字，适配器放出 116,500 枚 rsETH，而 Unichain 上并没有对应的销毁[1]。按 Galaxy 的分析和 LayerZero 的说法，攻击者篡改了验证者读取链上数据所用的两个 RPC 节点，同时对其余节点发动 DDoS，让验证者只能读到伪造的数据；签名密钥没有泄露[3][4]。随后一笔 40,000 枚的提取因 Kelp 冻结了接收地址而失败[1]。

损失随后沿着借贷协议扩散。攻击者把其中 89,567 枚 rsETH 存进以太坊和 Arbitrum 上的 Aave，借走 82,650 枚 WETH[1]。远端链上的 rsETH 失去了大部分储备，市场担心 Aave 出现坏账，两天内 DeFi 总锁仓减少约 130 亿美元，其中 Aave 流出约 85 亿美元[3]。

Arbitrum 安全委员会冻结了攻击者在该链上的 30,765.67 枚 ETH[5]。Aave 牵头的 DeFi United 联合 EtherFi、Lido、Mantle 等方筹资，并清算了攻击者在 Aave 和 Compound 上的抵押仓位，收回约 10.7 万枚 rsETH[10][11]。LayerZero 初步把攻击归因于朝鲜 Lazarus 旗下的 TraderTraitor，本站没有查到执法机构的公开确认[4]。谁该为单一验证者的配置负责，双方各执一词。2026 年 9 月，Kelp 在加拿大不列颠哥伦比亚省起诉 LayerZero 及其 CEO Bryan Pellegrino[15][16]。

背景

rsETH 的跨链储备

Kelp 是一个流动性再质押协议：用户存入 ETH 或 LST，换得生息凭证 rsETH。主网上的 rsETH 由 Kelp 的质押存款支撑；L2 等远端链上的 rsETH 是跨链副本，储备全部锁在以太坊的适配器里。Aave 服务商的事故报告把这套机制必须满足的条件写成一个不等式：以太坊适配器锁定的 rsETH 不少于所有远端链铸出的 rsETH 总量[1]。

验证者由应用自己选

在 LayerZero V2 中，一条跨链消息是否可信由 DVN（去中心化验证网络）判断。每个应用为每条入站路径单独配置：必须签字的 required DVN、可选 DVN 及其阈值，以及源链需要的区块确认数[17]。配置多严，由应用自己决定。按 ForkLog 引用的 Dune 数据，约 2,665 个活跃的 OApp 合约中约有 47% 使用 1-of-1 配置[14]。

借贷市场里的 rsETH

rsETH 是 Aave 上的主要抵押品之一。Galaxy 指出，Aave 在 2026 年 1 月把 E-Mode 下以 rsETH 借 WETH 的 LTV 从 72% 上调到 93%，同期 SparkLend 的上限是 72%，Fluid 约 75%[3]。抵押率越高，桥一旦出事，借贷协议承担的坏账风险越大。

攻击原理

这次没有合约漏洞。适配器、EndpointV2 和接收库都按设计运行，出问题的是对“这条消息是真的”的判断：按应用的配置，一个 DVN 的签字就足够了。下面是 LayerZero V2 接收库里决定消息能否通过验证的代码：

// UlnBase.sol：每条路径的验证配置
struct UlnConfig {
    uint64 confirmations;
    uint8 requiredDVNCount;
    uint8 optionalDVNCount;
    uint8 optionalDVNThreshold; // (0, optionalDVNCount]
    address[] requiredDVNs;
    address[] optionalDVNs;
}

// ReceiveUlnBase.sol：所有 required DVN 都签了字，且没有可选 DVN 时，直接通过
function _checkVerifiable(
    UlnConfig memory _config,
    bytes32 _headerHash,
    bytes32 _payloadHash
) internal view returns (bool) {
    // iterate the required DVNs
    if (_config.requiredDVNCount > 0) {
        for (uint8 i = 0; i < _config.requiredDVNCount; ++i) {
            if (!_verified(_config.requiredDVNs[i], _headerHash, _payloadHash,
                    _config.confirmations)) {
                // return if any of the required DVNs haven't signed
                return false;
            }
        }
        if (_config.optionalDVNCount == 0) {
            // returns early if all required DVNs have signed and there are no optional DVNs
            return true;   // 1-of-1 配置：唯一的验证者签了字，就走到这里
        }
    }
    // ……（可选 DVN 的阈值判断）……
}

来源：LayerZero-Labs/LayerZero-v2 仓库 main 分支，packages/layerzero-v2/evm/messagelib/contracts/uln/UlnBase.sol 第 8–16 行（去掉了两行原注释）、ReceiveUlnBase.sol 第 90–107 行，一处长行折行。

代码本身没有错，它如实执行了应用给出的配置。Kelp 的 Unichain→以太坊路径是 1-of-1：一个 required DVN，没有可选 DVN[1]。这个 DVN 的判断一旦出错，链上没有第二个独立的来源可以否决它。

验证者是怎么被骗的

DVN 要确认“Unichain 上确实发生了这笔销毁和发送”，靠的是通过 RPC 节点读取 Unichain 的链上数据。按 Galaxy 的分析，攻击者控制了 DVN 依赖的两个下游 RPC 节点，让它们返回伪造的数据，同时对没有被控制的节点发动 DDoS，迫使 DVN 切换到被控制的节点上[3]。Decrypt 转述的分析称，节点上的恶意软件在执行后会删除自己的程序和日志[4]。LayerZero 表示签名密钥没有泄露，这是对基础设施的操纵，不是合约漏洞[3]。

结果是，DVN 为一个编号为 308 的消息签了字，以太坊接受了它；而 Unichain 上的出站编号仍停在 307，说明这条消息从未在源链上发出。适配器的余额从攻击前一个区块的 116,723 枚 rsETH 降到 223 枚[1]。

坏账为什么落在 Aave

被放出的 rsETH 本身没有问题，问题是远端链上的 rsETH 失去了储备。Aave 服务商的报告统计，远端链上的 rsETH 合计 152,577 枚，而适配器里只剩 Kelp 抢先撤出的 40,373 枚，缺口约 112,204 枚[1]。攻击者把 rsETH 按高抵押率存进 Aave 借走 WETH，7 个地址的健康因子停在 1.01 到 1.03 之间。只要 rsETH 被重新定价，这些仓位就会变成坏账。Galaxy 按两种分摊方式估算，Aave 的坏账在 1.237 亿到 2.301 亿美元之间[3]。

LayerZero 的说法

曾多次建议 Kelp 使用多个验证者；事后不再为单一验证者配置的应用签字[4]。5 月承认“允许我们的 DVN 以 1/1 方式处理高价值交易是个错误”[14]。

Kelp 的说法

这套配置事先与 LayerZero 讨论过，并被确认是安全的；LayerZero 在事前书面审阅并认可了它的部署和配置，事后却把责任推给 Kelp[16]。

两种说法都还没有经过法院审理。

攻击过程

以下按已公开的事故报告和报道转述，只写结论和每一步本可以在哪里拦住[1][3][4]。

  1. 污染数据源攻击者控制了 LayerZero Labs DVN 依赖的两个 RPC 节点，并对其余节点发动 DDoS，迫使 DVN 只能读取被控制的节点。如果 DVN 在数据源不一致或不可用时停止签字，而不是切换到剩下的节点，这一步就不会生效。
  2. 伪造消息通过验证DVN 为一条源链上不存在的消息签了字。路径配置是 1-of-1，接收库凭这一个签字判定通过，适配器放出 116,500 枚 rsETH。第二个独立运营、使用不同数据源的 DVN 可以在这里拦住它；桥合约如果有单笔或单位时间的放币上限，损失也会小得多。
  3. 换成真实资产几分钟内，rsETH 被分散到 7 个地址，其中 89,567 枚存进以太坊和 Arbitrum 上的 Aave，借出 82,650 枚 WETH 和约 821 枚 wstETH；另有 17,426 枚进了 Compound，约 5,211 枚在 DEX 上卖出[11]。如果借贷协议对跨链副本设了更低的抵押率或更小的供给上限，能借走的 ETH 会少得多。
  4. 第二次尝试失败第二条伪造消息（40,000 枚 rsETH）同样通过了验证，但 Kelp 已经冻结了接收地址，执行失败。Kelp 随即从适配器撤出剩下的 40,373 枚 rsETH[1]。

金额与日期的口径

损失金额按 116,500 枚 rsETH 折算，Galaxy 写作约 2.9 亿美元[3]，CoinDesk、Cointelegraph 写作 2.92 亿美元[15][16]。CoinDesk 的诉讼报道把攻击日期写成 4 月 22 日，与 Aave 服务商报告的区块时间（4 月 18 日）不符，本页以 4 月 18 日为准[1]。

影响

借贷协议的挤兑

Aave 冻结了 rsETH 市场，又在六个部署上冻结 WETH 并把 WETH 的 LTV 设为 0[2][11]。存款人担心坏账，Aave 的锁仓两天内从约 264 亿美元降到约 179 亿美元，其中 ETH 和 WETH 流出约 54 亿美元；整个 DeFi 的锁仓 48 小时内减少约 130 亿美元[3]。被盗的是一个再质押代币的跨链储备，挤兑却落在了最大的借贷协议上。

沿着收益策略扩散

Lido 的 stETH 和 wstETH 没有受影响，但它的 EarnETH 策略持有与 rsETH 相关的仓位，又受借款利率飙升的牵连，最坏情况下的风险敞口约 9,000 ETH，当时约合 2,100 万美元。Lido Earn 和 Mellow 暂停了金库的资金进出，协调平掉杠杆仓位[13]。

跨链安全

按 ForkLog 引用的 Dune 数据，事发时约 47% 的活跃 OApp 合约使用 1-of-1 配置[14]，Kelp 只是其中一个。这起事件把跨链桥安全的问题从“签名者有几个”推进到“签名者读的是什么数据”。早年的跨链桥大案多出在签名密钥上，如 Ronin；这次密钥完好，被骗的是验证者的数据来源。合约验证逻辑出错的案例可以对照 Nomad 和 Wormhole。

后续处置

Arbitrum 冻结与它引起的争议

Arbitrum 安全委员会的做法是在以太坊上原子地升级 Inbox 合约，加入一个可以冒充任意发送者的函数，以攻击者地址的名义发起一笔跨链交易，把 30,765.67 枚 ETH 转到一个特殊地址，再把合约恢复原样。要释放这笔钱，必须经过 Arbitrum 治理[5]。一个 L2 的安全委员会可以替用户地址“签字”转走资产，这在社区里引起了争论：有人据此说 Arbitrum 不够去中心化，也有人认为这正是安全委员会存在的意义。一位社区成员在治理论坛开帖，主张把这类紧急权限的边界事先写清楚[7]。

释放的过程又牵出了法院。持有对朝鲜恐怖主义赔偿判决的原告申请限制令，要求不得转移这笔 ETH。Aave LLC 提出紧急动议，认为限制令建立在“攻击者是 Lazarus”这一未经证实的推测上，并称暂时持有被盗资产不等于拥有它[8]。5 月 8 日，纽约南区联邦法院的 Margaret M. Garnett 法官修改限制令，允许 Arbitrum DAO 投票把这笔 ETH 转入 Aave LLC 控制的钱包，条件是 Aave LLC 此后受同一限制令约束[9]。Arbitrum DAO 的投票以 90.96% 赞成通过[8]。

DeFi United

Aave 把这次救助称为 DeFi United。4 月 24 日的治理提案列出的首批参与方包括 EtherFi、Lido、Mantle、Ethena、Ink Foundation、Golem Foundation、BGD Labs 等[10]。Lido 提议拿出至多 2,500 枚 stETH，专门用来缩小 rsETH 的缺口[12]；Mantle DAO 经链上投票加入[11]。接收资金的救助多签按社区意见从 2/3 改为 3/4，增加 EtherFi 为签名人[6]。

最关键的一步是 5 月 6 日的清算：Aave 用一个专门构造的治理提案清算了攻击者的仓位，连同 Compound 共收回 106,993 枚 rsETH，约占远端链 112,103 枚无储备 rsETH 的 95%；剩下的约 5,211 枚由 DeFi United 承诺的 ETH 补足。5 月 9 日，Aave 提议恢复 WETH 的 LTV、解除冻结[11]。各方实际出资的总额，本站没有找到可核实的最终数字。

LayerZero 的改动

LayerZero 在事发两天后宣布不再为单一验证者配置的应用签字[4]。5 月，它承认允许自己的 DVN 以 1/1 方式处理高价值交易是个错误，把默认配置改为 5/5、至少 3/3，并开发第二个 DVN 客户端和名为 Console 的监控平台[14]。

诉讼与归因

2026 年 9 月 25 日，Kelp 背后的公司在不列颠哥伦比亚省对 LayerZero 和 Pellegrino 提起民事诉讼，指控 LayerZero 没有披露其技术固有的风险，没能阻止基础设施被渗透，事后又公开把责任推给 Kelp。Pellegrino 称诉讼“毫无依据”，表示会在温哥华应诉[15][16]。

攻击者的归属目前只有 LayerZero 的初步判断：“很可能”是朝鲜 Lazarus 旗下的 TraderTraitor。安全公司 Cyvers 没有附和这一归因[4]，Aave LLC 在法庭上也称它是未经证实的推测[8]。截至 2026 年 10 月，本站没有查到 FBI 等执法机构的公开认定。

教训与防御

给跨链应用
  • 高价值路径不要只靠一个验证者。用 required 加 optional 的阈值组合多个独立运营的 DVN，LayerZero 事后的默认值是 5/5、至少 3/3[14]。
  • 把配置当成安全边界来管理：谁改的、谁审过、依据是什么，都要留下记录。这次“谁选了 1-of-1”成了诉讼的焦点。
  • 给桥合约加单笔和单位时间的放币上限。116,500 枚 rsETH 一次放出，约占适配器全部余额。
给验证者运营方
  • 数据源不一致或不可用时停止签字，而不是切换到剩下的节点。攻击者发动 DDoS，正是为了逼出这次切换[3]。
  • 交叉核对多个独立运营的 RPC 来源，并把源链状态的检查做进签字前的最后一步，例如出站编号是否真的推进了。
给借贷协议和治理
  • 跨链副本的风险高于主网原生资产，抵押率和供给上限要反映桥的风险。93% 的 LTV 让伪造的 rsETH 几乎能等额换成 WETH[3]。
  • 紧急冻结权限救回了 3 万多枚 ETH，也引出了权限边界和法院管辖的争议。能做什么、谁来批准、事后如何释放，最好事先写进规则。
