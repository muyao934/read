Balancer V2 舍入误差攻击

2025 年 11 月 3 日，攻击者利用 Balancer V2 稳定池在“精确输出”兑换中把金额向下取整的问题，在一笔交易里先把池子抽到只剩几 wei，再用几十次小额兑换放大舍入误差、压低 BPT 价格，然后低价补回 BPT，带走池中资产。同样的操作在半小时内复制到了多条链和多个分叉协议上。这段代码已运行四年、经过多家公司审计；事后 Berachain、Gnosis Chain 和 Sonic 分别动用了停链、硬分叉和地址冻结，Balancer 自己也在一年内走向关停。

概要

Balancer V2 的所有池子共用一个 Vault 托管资产，池子合约只负责定价。Composable Stable Pool（下文简称 CSP）用于价格相近的资产，例如 WETH 和 wstETH、osETH 这类流动性质押代币。它把自己的 LP 代币 BPT 也登记为池中代币，让加入和退出流动性可以写成普通的兑换。池子计算前，要把余额和兑换金额乘上“缩放因子”，即精度换算再乘以代币汇率，这一步一律向下取整。在“精确输出”（GIVEN_OUT）兑换里，被向下取整的恰好是池子要付出去的数量，池子因此会少算调用者应付的数量[1][3]。

这个误差平时不到 1 wei，可以忽略。攻击者在同一笔 batchSwap 里先用并不持有的 BPT 换走池中几乎全部代币，把余额压到个位数 wei，这时一次截断就相当于金额的 5% 到 10%。接着是几十次算好数量的小额兑换，每次都少付一点，池子的不变量 D 越来越小，BPT 的价格随之下降。最后攻击者按压低后的价格买回 BPT 还清欠款，多出的代币记在自己的 Vault 内部余额里，再用另一笔交易提走[5][6]。

按 Balancer 官方统计，自家部署的池子被转走约 1.21 亿美元，扣除 StakeWise 和白帽追回的约 2,650 万美元，攻击者实际拿走约 9,490 万美元；另有约 1,940 万美元因池子及时暂停而保住，约 710 万美元在 Gnosis Chain 上被验证者冻结[1]。常被引用的 1.28 亿美元来自安全公司 PeckShield，统计口径不同，“资金去向”一节有对照[15]。攻击者至今没有被任何执法机构或安全公司公开认定。

背景

Balancer 是以太坊上历史最久的 AMM 之一[14]。V2 的核心设计是把所有池子的资产集中放在一个 Vault 合约里，池子合约只提供定价逻辑。Vault 支持 batchSwap：一笔交易可以串联多次兑换，中途每个代币的进出只记账，最后才按净额结算。用户还可以把资产留在 Vault 里作为“内部余额”，省去反复转账[1]。这次被攻击的代码在 V2 上运行了四年多[29]。

稳定池使用 Curve 的 StableSwap 不变量 D，适合价格接近 1:1 的资产。CSP 在普通稳定池上加了两样东西。一是 rate provider：wstETH、osETH、rETH 这类收益型代币相对 ETH 的汇率会慢慢上涨，池子计算前要先把它们折算成底层资产的数量。二是“可组合”：池子预铸大量自己的 BPT 并把它登记为池中代币，用代币换 BPT 就等于单币加入流动性（joinSwap），用 BPT 换代币就等于单币退出（exitSwap），两者都能放进 batchSwap[1][3]。Balancer 事后的分析指出，正是这两个特性让一个原本可以忽略的舍入问题变得可以利用。

Balancer V2 被 OpenZeppelin、Trail of Bits、Certora 和 ABDK 四家公司审计过 11 次[17]。OpenZeppelin 事后追溯，带汇率的缩放因子是 2021 年 7 月 16 日先加进 MetaStablePool，9 月 1 日加进 Linear Pool，9 月 20 日加进 StablePhantomPool，也就是后来的 ComposableStablePool；它当年的两轮审计都不包括这些池子[5]。Trail of Bits 在 2021 年 10 月的 Linear Pool 审查中报告过同类问题，编号 TOB-BALANCER-004，当时无法证明可以获利，严重性记为“未确定”；2022 年 9 月它审查 CSP 时，StableMath 库不在范围内[4]。

CSP 的工厂合约带“暂停窗口”：窗口期内，获授权的地址可以暂停池子；窗口一过，池子就永远不能暂停。2024 年 2 月部署的 v6 工厂与 2023 年 7 月的 v5 功能相同，只是把暂停窗口延长到 4 年、缓冲期 6 个月[7]。事发时，v6 池子仍在窗口期内，v5 池子的窗口已经过期[1][15]。

这也不是 Balancer V2 第一次因为池子出问题。Balancer 后来说，团队是在 Linear Pool 漏洞之后决定不再逐步修补 V2、改为重写 V3 的[31]。V3 于 2024 年 12 月上线，架构和代码完全不同，这次没有受到影响[1]。

漏洞原理

Balancer V2 的兑换有两种：GIVEN_IN 指定付出多少、求能换到多少；GIVEN_OUT 指定要拿走多少（amountOut），求要付多少（amountIn）。池子内部的数学一律按 18 位精度计算，所以进入公式之前，余额和金额都要乘上每个代币的缩放因子。CSP 的缩放因子等于精度换算乘以代币汇率[2]。WETH 的汇率是 1，缩放因子是整数倍，乘完不丢精度；osETH、wstETH 的汇率略大于 1，缩放因子是一个不整齐的 18 位小数，乘完必须取整，取整的方向就成了问题。下面是 GIVEN_OUT 兑换的处理函数。CSP 重写了它，但只是把涉及 BPT 的兑换分流出去，普通代币之间的兑换仍然调用这段父类代码：

// BaseGeneralPool.sol，GIVEN_OUT 兑换（CSP 中非 BPT 代币之间的兑换走这里）
function _swapGivenOut(
    SwapRequest memory swapRequest,
    uint256[] memory balances,
    uint256 indexIn,
    uint256 indexOut,
    uint256[] memory scalingFactors
) internal virtual returns (uint256) {
    _upscaleArray(balances, scalingFactors);
    // 此时 swapRequest.amount 是调用者要拿走的 amountOut，被 _upscale 向下取整
    swapRequest.amount = _upscale(swapRequest.amount, scalingFactors[indexOut]);

    uint256 amountIn = _onSwapGivenOut(swapRequest, balances, indexIn, indexOut);

    // amountIn tokens are entering the Pool, so we round up.
    amountIn = _downscaleUp(amountIn, scalingFactors[indexIn]);

    // Fees are added after scaling happens, to reduce the complexity of the
    // rounding direction analysis.
    return _addSwapFeeAmount(amountIn);
}

来源：balancer/balancer-v2-monorepo，pkg/pool-utils/contracts/BaseGeneralPool.sol 第 68–85 行（去掉一层缩进，长注释折行）；CSP 的分流逻辑见 pkg/pool-stable/contracts/ComposableStablePool.sol 第 218–235 行。

// ScalingHelpers.sol
function _upscale(uint256 amount, uint256 scalingFactor) pure returns (uint256) {
    // Upscale rounding wouldn't necessarily always go in the same direction: in a swap for
    // example the balance of token in should be rounded up, and that of token out rounded
    // down. This is the only place where we round in the same direction for all amounts,
    // as the impact of this rounding is expected to be minimal.
    return FixedPoint.mulDown(amount, scalingFactor);   // 一律向下取整
}

// ComposableStablePoolRates.sol：缩放因子 = 精度换算 × 代币汇率，本身也是向下取整
function _scalingFactors() internal view virtual override returns (uint256[] memory) {
    // ……
    for (uint256 i = 0; i < totalTokens; ++i) {
        scalingFactors[i] = _getScalingFactor(i).mulDown(_getTokenRate(i));
    }
    // ……
}

来源：同上，pkg/solidity-utils/contracts/helpers/ScalingHelpers.sol 第 35–40 行（长注释折行）；pkg/pool-stable/contracts/ComposableStablePoolRates.sol 第 270–280 行（中间从略）。

amountOut 是池子要付出去的数量。按“取整要对池子有利”的原则，它应该向上取整。_upscale 的注释写得很清楚：这是全库唯一一处不分方向的取整，作者认为影响很小。Certora 指出，向下取整让 amountOut 被少算，StableMath 据此算出的应付数量也跟着偏少[3]。后面的代码确实在往“多收”的方向取整：_downscaleUp 向上取整，StableMath 在结果上再加 1。Balancer 的 post-mortem 说，由于 StableMath 的计算方式，amountIn 最终同样被向下取整，调用者为同样的 amountOut 付得太少[1]。

// StableMath.sol，_calcInGivenOut 的主体（参数从略）
// Amount in, so we round up overall.
balances[tokenIndexOut] = balances[tokenIndexOut].sub(tokenAmountOut);
// tokenAmountOut 已经是被向下取整过的 amountOut

uint256 finalBalanceIn = _getTokenBalanceGivenInvariantAndAllOtherBalances(
    amplificationParameter, balances, invariant, tokenIndexIn
);

balances[tokenIndexOut] = balances[tokenIndexOut] + tokenAmountOut;

return finalBalanceIn.sub(balances[tokenIndexIn]).add(1);   // 结果再加 1，往“多收”方向修正

来源：同上，pkg/pool-stable/contracts/StableMath.sol 第 184–198 行（省略中间一段英文注释，参数合并为一行）。

开发者处处留意了 amountIn 的取整方向，漏掉的是 amountOut 在进入公式之前就已经少算了这一步。被截掉的部分不到 1 wei，余额正常时 Certora 称之为可以忽略的“差一”误差[3]。OpenZeppelin 给了一个例子：amountOut 为 17、缩放因子为 1.058132408689971699 时，精确值约为 17.988，mulDown 之后只剩 17，少计了约 5.5%[5]。Check Point 的分析指出，当代币余额落在 8 到 9 wei 时，一次缩放最多会损失约 10% 的相对精度；余额同样经过向下取整的 _upscaleArray，误差会一路传进不变量 D，让 D 被低估[6]。

三个前提

Balancer 的 post-mortem 列出了利用这个漏洞的三个前提：GIVEN_OUT 兑换的取整错误；rate provider 带来不整齐的缩放因子；池子处于极低流动性状态，把误差放大到可以获利。只有同时用了 rate provider 和池内 BPT 的 CSP 三条都满足，少数没有用收益型代币的 CSP 也不受影响[1]。

池子类型前提是否满足结果
Composable Stable Pool（带 rate provider）三条都满足被攻击。v6 池子被及时暂停，v5 池子已过暂停窗口
普通 Stable Pool没有 rate provider未受影响
MetaStable Pool有 rate provider，但不满足低流动性条件这条路径不受影响。事后 Certora 等发现了另一条提取路径，约 410 万美元被抢先转移保护
Weighted Pool没有 rate provider，数学完全不同未受影响。幂函数误差大，代码本身带有更大的补偿，单个 wei 的误差被淹没
Gyro Pool使用虚拟余额未受影响。真实余额的微小变化不影响结果
Balancer V3精度换算由 Vault 统一处理，每步运算都规定取整方向未受影响

把 BPT 放进池子

第三个前提最关键。V2 的 Vault 不可重入，原本没法在同一笔交易里既加入或退出流动性、又做兑换。CSP 把自己的 BPT 当成池中代币，加入和退出就变成了兑换，可以和其他兑换一起写进 batchSwap[1]。batchSwap 只在最后核对净额，中途允许出现欠款，用 Certora 的话说，用户可以暂时欠 Vault 一笔 BPT[3]。攻击者因此能在交易中途“借”来任意数量的 BPT，用它换空池子，在极低的余额下反复利用取整误差，最后再把 BPT 补上。

修法是对池子要付出的数量向上取整。下面是示意，不是 Balancer 发布的补丁。V2 的池子合约不可升级，事后能做的只有暂停、开启 Recovery Mode、禁用工厂和引导 LP 迁移到 V3[1]：

// 示意：GIVEN_OUT 路径按资金流向分别取整
_upscaleArray(balances, scalingFactors);
// 池子要付出的 amountOut 向上取整，据此算出的 amountIn 只会偏多
swapRequest.amount = FixedPoint.mulUp(swapRequest.amount, scalingFactors[indexOut]);
uint256 amountIn = _onSwapGivenOut(swapRequest, balances, indexIn, indexOut);
amountIn = _downscaleUp(amountIn, scalingFactors[indexIn]);

示意代码。V3 的做法是让池子数学本身按正确方向取整，ExactOut 兑换的 amountIn 取整已经改正，计算时还把 tokenIn 的余额向上取整；此外给每个代币设了最低余额，让池子无法被压到极低状态[29]。

为什么四年没人发现

Trail of Bits 事后写道，模糊测试第一次找到“方向错了的 1 wei 精度损失”时，它看起来无关紧要；只有在低流动性、特定参数的池子里，这点损失才可能大到有利可图[4]。Certora 2022 年对 V2 稳定池的形式化验证证明了总体偿付能力，例如 BPT 余额不超过总量、不存入资产就不能铸出 BPT，但这些性质不约束单次兑换的取整。它事后列出两条本可以抓住这个漏洞的性质：往返兑换不能获利；任何操作都不能让单个 BPT 的价值下降[3]。

攻击过程

以太坊上的主攻击由两笔交易完成。下面的步骤综合了 Check Point 对交易的还原、OpenZeppelin 的分析和 Balancer 的 post-mortem[1][5][6]。

  1. 准备攻击地址 0x506D1f9EFe24f0d47853aDca907EB8d89AE03207 的启动资金经 Tornado Cash 转入[14][18]。rekt.news 发现，攻击者事先在链上部署了一个“数学辅助”合约，专门计算每一步兑换的最佳数量[15]。
  2. 部署即攻击07:46:47（UTC），区块 23,717,397，攻击者部署攻击合约 0x54B53503c0e2173Df29f8da735fBd45Ee8aBa30d。合约的构造函数直接对 osETH/WETH 和 wstETH/WETH 两个 CSP 执行 batchSwap，部署完成时盗窃已经完成[6][26]。
  3. 第一阶段：用借来的 BPT 抽空池子攻击者用 exitSwap 把池中几乎全部 WETH 和 osETH 换走。这些 BPT 攻击者并不持有，batchSwap 允许先欠后还[1][3]。
  4. 第二阶段：几十次小额兑换余额只剩几 wei 后，攻击者按事先算好的数量做 GIVEN_OUT 兑换。Check Point 在这一次部署中数出 65 轮：先用较大的兑换把某个代币的余额推到 8 到 9 wei 的临界点，再用小额兑换触发取整损失。每轮付给协议费用收集合约的 osETH 从约 0.414 枚降到接近 0，说明池子一轮比一轮小[6]。
  5. 第三阶段：低价补回 BPT不变量 D 被压低，BPT 价格随之下降。攻击者用 joinSwap 存入少量代币，换回 BPT 还清第一阶段的欠款。Vault 只核对净额，多出来的代币记在攻击合约的内部余额里。两个池子合计为 6,586 WETH、6,851 osETH 和 4,259 wstETH[6]。
  6. 提走07:48:11，区块 23,717,404，攻击者调用合约的 0x8a4f75d6 函数，由它调用 Vault 的 manageUserBalance，把内部余额转到外部地址 0xAa760D53541d8390074c61DEFeaba314675b8e3f[6][26]。
  7. 多链复制同样的操作几乎同时出现在 Arbitrum、Base、Optimism 和 Polygon 上[1]。数学辅助合约的源码在链上可读，rekt.news 的说法是“改掉池子地址和收款地址，部署，获利”。27 个 V2 分叉继承了这段代码，一周后仍有模仿攻击[15]。
早期的误判

事发当天，Halborn、Nansen 的分析师和多家媒体把原因归于 manageUserBalance 的权限检查有误，因为资金是通过这个函数提走的[16][17][18][28]。Balancer 的 post-mortem 明确说，内部余额功能本身与漏洞无关，攻击者只是把赃款暂存在那里[1]。

没有执法机构或安全公司公开认定攻击者身份。Balancer 说它的法务团队在与多个司法辖区的执法部门合作[1]。

影响

Balancer 本身

事发当天，BAL 一小时内下跌约 8%[16]；Balancer 的 TVL 在 24 小时内从 6.26 亿美元降到 3.38 亿美元，借贷协议 Venus 暂停了 BAL 借款并把它的抵押率设为零[15]。此后几个月，团队人数从约 25 人减到 12.5 个全职岗位，年度预算降到 190 万美元；而 DAO 每年分到的协议收入只有约 29 万美元[21]。2026 年 3 月，联合创始人 Fernando Martinelli 宣布关闭 Balancer Labs，说这家公司“已经成了协议的负担而不是资产”，当时 Balancer 的 TVL 约 1.57 亿美元，比 2021 年底的峰值低 95%[20]。据 DefiLlama 的数据，2025 年 9 月 28 日到 2026 年 9 月 29 日，Balancer 的 TVL 下降了 93.6%[32]。

提出关停的 BIP-928 并没有把原因全算在这次攻击上。它给出的核心理由是收入：每月成本约 15 万美元，2026 年 8 月的协议收入约 3 万美元，大部分收入仍来自 V2，V3 的收入没有增长到能接替它[24][25]。提案这样描述攻击的作用：

2025 年 11 月的攻击打在旧的 V2 池子上。V3 是另一套架构，但这件事从此跟着 Balancer 这个名字出现在每一次谈话里，让增长更难。它是 4 月的计划比看上去更难的原因之一，但不是这份提案的依据。

Marcus Hardt，BIP-928 提案正文，2026 年 9 月（本站译）[24]

分叉和下游协议

Balancer V2 的代码被大量复制。rekt.news 统计有 27 个 V2 分叉继承了这段代码，损失最大的是 Berachain 上的 BEX 和 Sonic 上的 Beets[15]。Beefy、Aura 等建立在 Balancer 池子之上的协议也在事发后紧急排查敞口[1]。

链级干预之争

这次事件里，至少三条链和两家代币发行方直接改写或冻结了攻击者的资产：Berachain 停链并硬分叉，Gnosis Chain 先软分叉后硬分叉，Sonic 冻结地址；StakeWise 销毁并重铸 osETH 和 osGNO，Monerium 冻结 EURe[9][12][15]。rekt.news 还称 Polygon 的验证者直接审查了攻击者的交易[15]。

支持干预

Gnosis 联合创始人 Martin Köppelmann 说，推动软分叉的动因是保护用户：Gnosis 对普通人推广“低风险 DeFi”，出了事就不能什么都不做。Gnosis 方面强调，本链有 344 个钱包受影响；受影响资金的大头属于 GnosisDAO 自己，但不到其国库的 2%，出手主要是为了散户。Rotki 创始人 Lefteris Karapetsas 认为，链有能力纠正时选择不作为“并不是中立”[14]。

反对或担忧

RealT 团队的成员担心开先例，以后每次被盗都可能被要求分叉。有人估计，号称约 34 万个验证者，真正独立的运营者可能只有 100 到 300 个；也有人说，不到 60 个人达成一致就能改写链上状态。还有人指出双重标准：同一个 EURe/sDAI 池子此前因预言机配置错误让 LP 损失了数十万欧元，当时没有人干预[14]。

Gnosis 事后达成的原则是：默认不干预，例外必须对照事先商定的标准，长期目标是让干预越来越难、最终不可能[14]。rekt.news 的评论更直接：代码就是法律，直到它让用户损失九位数，每条链突然都想起自己有管理员钥匙[15]。类似的选择在这次事件前后都出现过。此前有 2016 年 The DAO 之后的以太坊硬分叉，2025 年 5 月 Cetus 被盗后 Sui 验证者冻结攻击者地址；此后有 2026 年 8 月 Cronos 为 Tectonic 被操纵一事回滚约两小时的链状态。

审计说明了什么

Balancer 事发当天强调自己“经过顶级公司的大量审计，漏洞赏金也运行了很久”。TAC 区块链的开发者关系负责人 Suhail Kakar 的回应是，Vault 被三家公司审计过，仍然丢了约 1.1 亿美元，“由某某审计”几乎说明不了什么[17]。审计方的回应集中在范围上：OpenZeppelin 说出问题的代码是在它的审计结束后才加进来的[17]；Certora 事后承认，偿付能力证明不够，余额总体守恒并不意味着取整安全[15]。

舍入误差也不是新的攻击类别。Trail of Bits 提到，2023 年的 Hundred Finance 和 2024 年的 Sonne Finance 都是被类似的舍入问题掏空的[4]。2026 年 8 月 31 日，Balancer V1 的一个池子又被同类手法攻击：SlowMist 分析，攻击者把 WBTC 储备压到接近零，再利用 18 位定点数反推输入数量时的误差，损失约 23.4 万美元[30]。

后续处置

当天的止损

Hypernative 07:52 报警，约 15 分钟后仍在暂停窗口内的 CSP v6 池子全部暂停，保住约 1,930 万美元，Crypto.com、Ether.fi 等大 LP 随后安全撤出；受影响池子开启 Recovery Mode，11 月 4 日关停 gauge，11 月 5 日禁用工厂。Certora 和 Trail of Bits 进入作战室做紧急复审，发现了 MetaStable 池子上的另一条提取路径，Balancer 与 Certora、SEAL 911 此后抢先把约 410 万美元转进受控地址[1]。v5 池子的暂停窗口已过，只能任由攻击者或白帽先动手。

赏金与退款

Balancer DAO 此前通过 BIP-726 采纳了 SEAL 安全港协议：白帽抢救资金后须交还 DAO，另领 10% 的赏金，单次上限 100 万美元，须提供真实姓名并通过 KYC 和制裁名单筛查。BIP-892 据此结算：Polygon 上的匿名白帽追回约 268 万美元，以太坊上的 Bitfinding 约 96.4 万美元，Base 上的匿名白帽约 16.1 万美元；Arbitrum 上的三笔因白帽不表明身份或拒绝 KYC，视为放弃赏金[8]。

退款不做社会化分摊：每个池子追回的钱只退给这个池子的 LP，按攻击前最后一个区块的 BPT 持仓比例，用追回的原币支付，通过 Merkle 合约领取，领取期 180 天。领取时须签署条款，免除 Balancer Labs、DAO、基金会及服务商与此次攻击相关的责任。Certora 参与的内部抢救不付赏金，全额退给 LP[8]。没有追回资金的池子，即攻击者拿走的约 9,490 万美元，没有补偿方案，Balancer 只承诺继续走执法和法律途径[1]。到 2026 年 7 月仍有约 92 万美元（约 500 ETH）无人领取，BIP-923 把领取期延长到 12 个月[22]。

对攻击者本人，Balancer 最初提出 48 小时内归还可得 20% 赏金，无人接受[14][17]。2026 年 2 月的 BIP-908 改为：归还资产或提供线索促成追回的人，可得追回额最多 10%，归还者免于被 DAO 起诉[19]。

StakeWise 的销毁与重铸

osETH 和 osGNO 的代币合约由 StakeWise DAO 所有，合约里的“控制者”可以在任意地址铸造或销毁代币。StakeWise 的 7 人紧急多签临时把控制者权限授予 DAO 地址，销毁攻击者钱包里的 osETH 和 osGNO，在 DAO 地址铸出等量代币，最后一笔交易撤销权限[11]。被盗的 6,851 枚 osETH 追回 5,041 枚，13,495 枚 osGNO 全部追回，按攻击前的 LP 持仓比例经 Merkle 分发[9]。StakeWise 说，这是紧急多签的权力第一次被动用，也应该是最后一次；它随即提出 SWIP-37，放弃 DAO 对这两个代币合约的所有权，因为这项权力本身就是中心化的攻击面[10][11]。

Gnosis Chain 的硬分叉

软分叉只能让攻击者的资金动不了，而且很脆弱：验证者一升级客户端，冻结就可能失效，钱也没法退给用户。Gnosis 花了约六周，让四个执行层客户端一起实现了一次“非常规状态转换”：在指定时间之后的第一个区块，把攻击者账户的代码换成一个只听救援地址指挥的转发合约[14]。

# Gnosis Chain 规范中的参考实现（伪代码）
def process_block(parent_header, block, state):
    if (
        parent_header.timestamp < BALANCER_HARDFORK_TIMESTAMP
        and block.header.timestamp >= BALANCER_HARDFORK_TIMESTAMP
    ):
        state.account(BALANCER_ATTACKER_ADDRESS).bytecode = BALANCER_RESCUE_BYTECODE
    # ... continue with regular block processing, including EIP-4788 and EIP-2935.

// 注入攻击者账户的合约（节选）
contract HardcodedForwarder {
    /// BALANCER_RESCUE_ADDRESS
    address public constant owner = 0x7Be579238a6a621601Eae2c346cDA54d68F7dfee;
    // execute(target, value, data)：只有 owner 能调用，只能调用合约地址
    // ……
}

来源：Gnosis 论坛《Balancer hack: claim process》转引的 gnosischain/specs 规范 execution/balancer_recovery.md。BALANCER_HARDFORK_TIMESTAMP 为 1766419900，即 2025-12-22 16:11:40（UTC）；BALANCER_ATTACKER_ADDRESS 为 0x506d…3207。

账户一旦有了代码，EIP-3607 就禁止它发起交易，攻击者手里的私钥因此作废；救援地址是一个 DAO 多签，可以以这个账户的身份调用 Balancer Vault 取回资产。余额、nonce 和存储都没有被改动，历史区块也没有被重写。这次硬分叉推迟了 Gnosis Chain 的 Fusaka 升级[13][14]。2026 年 2 月 26 日，Gnosis 公布了受影响地址和可领数量，随后通过 Merkl 开放领取；领取页面附带一个默认 5% 的可选捐赠，捐给参与救援的团队[14]。

Berachain 和 Sonic

Berachain 的验证者协调停链。基金会说，网络会在追回全部受影响资金后恢复；联合创始人 Smokey The Bera 估计约 1,200 万美元用户资金面临风险。由于被盗的不只是原生代币，简单回滚区块行不通，分叉可能涉及回滚或“前滚”[16]。rekt.news 称白帽救下了约 1,286 万美元，资金后来追回；Sonic Labs 则在攻击进行中上线了冻结机制[15]。本站没有找到两家的正式 post-mortem，Berachain 恢复出块的确切时间和 Sonic 冻结的金额都未能核实。

Balancer 的结局

2026 年 3 月 Balancer Labs 宣布关闭，必要的员工转入 OpCo[20]。4 月，运营重组的 BIP-918 和代币模型改革的 BIP-919 在 Snapshot 上勉强通过，赞成票只比反对票多 34 万到 41 万：团队减半，BAL 增发停止，协议费全部归 DAO[20][21][23]。

9 月 14 日，前 Balancer Labs CEO Marcus Hardt 在论坛提出 BIP-928，主张有序关停协议，把国库按比例分给 BAL 持有人，并取消 BIP-919 承诺的回购[24][25]。Snapshot 投票于 9 月 25 日至 29 日（UTC）进行：42 个地址投票，两个赞成选项合计约 1,709 万 BAL，反对约 14 万 BAL，法定人数为 500 万 BAL；同期由 MAXYZ 团队提出、要用国库 BAL 资助一个官方分叉的 BIP-929 以约 1,211 万对 521 万被否决[23][32]。10 月，不要国库资助、只请求 DAO 认可分叉的 BIP-932 通过；列出关停链上操作的 BIP-936 于 10 月 27 日通过：禁用 V2 和 V3 的池子工厂，10 月 30 日把 V2 的协议费默认值调为零，暂停仍在窗口期内的池子[23]。

按 BIP-928，可暂停的池子 10 月 30 日起只能提款，不能暂停的池子继续运行；2027 年 5 月底 veBAL 锁仓全部到期后，持有人销毁 BAL，按比例领取国库中的非 BAL 资产，分两轮，最后再清扫一次。关停预算为 2027 年 5 月前 15 万美元、此后 3 万美元，另有 22 万美元备用金[24]。

“每枚 BAL 约 0.158 美元”从哪来

这个数字出自 Hardt 2026 年 9 月 20 日在提案讨论帖里的测算：按 9 月 18 日的链上余额和当天价格，可分配的非 BAL 资产为 9,959,416 美元，可赎回的 BAL 为 63,068,821 枚，每枚约 0.1579 美元。他特别注明这是自己的测量，没有经过审计[24]。提案正文只说国库“至少 900 万美元”，最终数额要在第一轮开放的区块上重新测量并审计，会随代币价格变化[24][25]。

截至 2026 年 10 月底，Balancer 的池子已转为只能提款，攻击者拿走的约 21,000 ETH 已换成比特币，没有被追回，攻击者身份仍未公开。

教训与防御

给合约开发者
  • 取整方向逐处判断，让每一步的误差都落在对池子有利的一边。“这里影响很小，统一向下”正是这次的漏洞来源。Trail of Bits 提醒，“取整要对协议有利”这句话本身不足以覆盖边界情况，应当把每一处精度损失和取整方向写下来并给出推理[4]。
  • 在极端状态下测试：余额只剩几 wei、汇率不是 1、金额很小。正常状态下 1 wei 的误差可以忽略，极端状态下它可能是金额的 10%。
  • 把“往返兑换不能获利”“任何操作都不能让单个份额贬值”写成性质，交给模糊测试和形式化验证。只证明总体偿付能力不够。
  • 不要让单笔交易能把池子推到退化状态。V3 加了最低余额，也可以在每步之后检查不变量的变化。
  • 新池子类型、新的缩放因子都是新代码，要有新的审计范围。这次出问题的代码是在审计结束后才加进来的。
给协议和链的运营方
  • 暂停窗口是双刃剑。v6 池子还能暂停，保住了约 1,930 万美元；v5 池子的窗口已过，只能看着被掏空。到期即失效的保护，要在到期前想好替代方案。
  • 监控和安全港协议在这次事件中起了作用：报警在 6 分钟内发出，白帽在事先约定的法律框架下合法截下了数百万美元。
  • 代币合约里的紧急权力能追回资金，也是一个中心化的攻击面。StakeWise 用完就提议放弃，是一个可以参考的做法。
  • 链级干预的规则要事先定好。Gnosis 是在出事之后才开始讨论框架的，结论是默认不干预、例外须符合事先商定的标准。
