Mixin Network 云数据库被入侵

2023 年 9 月 23 日，Mixin Network 所用云服务商的数据库被黑客入侵，随后主网上的 BTC、ETH 等资产被转走，初步估计约 2 亿美元。官方至今只确认了“云服务商数据库被攻击”这一句，没有公布技术复盘。这起事件说明，一个以 BFT 共识自称去中心化的网络，用户资产的安全可能取决于一个普通的云数据库。

概要

Mixin Network 是一个以 BFT-DAG 共识运行的跨链转账网络，用户存入的 BTC、ETH 等资产放在 Mixin 管理的外链地址上。2023 年 9 月 23 日凌晨（香港时间），Mixin 所用云服务商的数据库被黑客入侵，主网资产被转走，初步估计约 2 亿美元[1][2]。Mixin 暂停了充值和提现，站内转账照常。

官方的技术说明只有“云服务商的数据库被黑客攻击”一句。数据库里存了什么、攻击者怎样拿到转走外链资产的签名能力，至今没有公开。可以确定的是，出问题的不是 Kernel 的共识，而是托管外链资产的那一层。2018 年的白皮书要求节点运行在 Intel SGX 可信执行环境里，开源代码的 README 则写着这部分“尚未集成”[11][12]。

创始人冯晓东先表示最多先赔付 50%，两天后公布按币种的比例：BTC 90%、ETH 30%、ERC20-USDT 10%[3][7]。缺口记成债务代币 MDT，用公司未来的利润回购。2026 年 9 月，Mixin 完成了 USDT 部分 2,300 万美元的兑付，BTC 和 ETH 部分没有公布时间表[9][10]。攻击者身份不明。

背景

Mixin Network 2017 年在香港成立，主打用手机号互相发送数字资产，早期天使投资人包括李笑来[3]。用户在 Mixin Messenger 等应用里看到的余额记在 Mixin 自己的账本上，背后对应的 BTC、ETH 等资产则存放在各条公链上由 Mixin 管理的地址里。

事发前，DefiLlama 统计的 Mixin 锁仓价值接近 4 亿美元，覆盖 48 条链；Mixin 7 月的月报披露协议中持有 9,544 枚 BTC，约合 2.53 亿美元[3]。它的开发者文档首页写着“所有资产都存放在 PoS-BFT-DAG 分布式网络中”[14]。

  9. 2024-01-31
    Mixin 正式推出债务代币 MDTb、MDTe、MDTu，分别对应 BTC、ETH、ERC20-USDT 债务，每枚价值 1 美元[8]。

    事件三周年当天，Mixin 宣布用经营利润完成 MDTu 对应的 2,300 万美元全额兑付[10]。截至 2026 年 10 月，本站没有查到 MDTb、MDTe 的兑付时间表。

攻击原理

这起事件没有公开的代码漏洞，官方也没有发布事故报告。下面先列出能确定的和不能确定的，再从 Mixin 公开的设计文档出发，解释一个云数据库为什么能影响链上资产。推断的部分会单独标明。

能确定的

  • 被攻击的是 Mixin 所用云服务商的数据库[1]。
  • 被转走的是公链上的 BTC、ETH 和 ERC20-USDT 等资产[1]。
  • Mixin 账本内部的转账照常进行，只暂停了充值和提现[2]。
  • 赔付比例按币种不同，说明各链受损程度不同[7]。

没有公开的

  • 是哪家云服务商，入侵是怎样发生的。
  • 数据库里存的是私钥、加密后的私钥、密钥分片，还是能调用签名服务的凭据。
  • 白皮书设计的 SGX 保护在 2023 年是否部署。
  • 最终确认的损失金额。

共识保护的是账本，不是链上的私钥

Mixin Kernel 是一个 BFT-DAG 账本，节点之间靠集体签名对账本快照达成共识，需要超过三分之二的节点签名[12]。这套共识能防止有人伪造 Mixin 账本上的余额，但它管不到比特币和以太坊。要把 BTC 从比特币网络上的一个地址转走，需要的是这个地址对应的私钥或密钥分片签名，这是 Kernel 共识之外的另一种能力。

2018 年的白皮书把这部分交给 Mixin Domain：Domain 为每种外链资产生成对应的地址，用户充值后由 Kernel 和 Domain 共同锁定，提现需要两者共同签名[11]。白皮书写道：

This works because the Mixin Kernel and the Mixin Domain is also a Proof of Stake network. Besides the XIN collateral, there are also additional Intel SGX enforcement for all related functions.

Mixin 技术白皮书草稿，2018-07-01，第 18 页[11]

意思是 Kernel 和 Domain 是靠 XIN 质押维持的权益证明网络，相关功能还额外由 Intel SGX 强制保护。但 Mixin Kernel 开源仓库 v0.1.0 和 v0.17.0 两个版本的 README，第一句都写着：“the Trusted Execution Environment is not integrated into this repository yet”[12]。现在的 README 则写明，充值需要托管方（custodian）授权，检查外链储备和执行外链提现“依赖单独的托管服务”[12]。

推断，不是官方结论

账本内转账照常、公链上的资产却被转走，这个结果说明攻击者拿到的不是篡改 Mixin 账本的能力，而是在公链上签名的能力，或者是让托管层替他签名的能力。按白皮书的设计，这部分本应由 SGX 和 Domain 节点保护；一个云数据库被入侵就能导致外链资产被转走，说明至少在 2023 年，签名所需的材料或调用签名的凭据可以通过这个数据库被拿到或被利用。具体是哪一种，Mixin 没有说明。

赔付比例也透露了一些信息。BTC 用户先拿回 90%，ETH 用户 30%，ERC20-USDT 用户只有 10%，其他链上的 USDT 不受影响[7]，这说明以太坊上的资产损失最重，与 PeckShield 统计的 ETH 约 9,448 万美元、由 USDT 换成的 DAI 约 2,355 万美元相吻合[1]。BTC.TOP 的江卓尔当时质疑，BTC 通常放在冷钱包里，本不该被一次云服务器入侵波及[3]。实际被转走的 BTC 约 2,330 万美元，说明至少有一部分 BTC 放在能在线签名的地址里。

事后的设计：用户自己持有一把钥匙

事件之后，Mixin 把安全宣传的重点转向 Mixin Safe。2026 年的报道把它描述为针对单一密钥风险的改进[10]。它的比特币账户是一个原生多签脚本，项目 README 给出的策略如下[13]：

// Mixin Safe 比特币账户的 miniscript 策略：3 把钥匙里任意 2 把签名即可花费
thresh(2,pk(OWNER),s:pk(MEMBERS),sj:and_v(v:pk(RECOVERY),n:older(52560)))
// OWNER    用户自己保管的钥匙
// MEMBERS  由 Mixin Safe 节点用 MPC 生成、共同控制的钥匙
// RECOVERY 恢复钥匙，要等 52,560 个区块（约一年）的时间锁到期后才能参与签名

来源：MixinNetwork/safe 仓库 README。中文注释为本站所加。

按这个脚本，在时间锁到期前，只有 OWNER 和 MEMBERS 同时签名才能动用资金。即使服务端全部失守，没有用户手里的那把钥匙，也转不走 BTC。时间锁到期后，MEMBERS 加 RECOVERY 也能花费，这是为用户丢失钥匙准备的退路。2023 年的托管方式缺的正是这种“服务端单独签不了”的约束。

攻击过程

Mixin 没有公布入侵经过，公开资料里能还原的只有链上可见的部分：

  1. 入侵云数据库2023 年 9 月 23 日凌晨（香港时间），Mixin 所用云服务商的数据库被入侵[1]。云服务商的名字和入侵方式都没有公开。
  2. 转出外链资产攻击者把 Mixin 主网在以太坊、比特币等公链上的资产转到自己的地址。PeckShield 识别出约 1.41 亿美元[1]。
  3. 规避冻结攻击者把 USDT 换成 DAI。USDT 的发行方 Tether 可以冻结地址，DAI 没有中心化的冻结功能[1]。
  4. 长期静置资金此后在攻击者地址里停留了约两年。2026 年 2 月，被标记为“Mixin Hacker”的钱包开始把 ETH 转入 Tornado Cash[9]。

链上分析平台 0xScope 当时指出，一个与攻击者有关的地址在 2022 年曾从 Mixin 收到 5 枚 ETH，之后向 Binance 存入 5.9 枚 ETH[1][6]。这条线索后来是否帮助确认了攻击者身份，公开资料里没有下文。

资金去向

  1. Mixin 外链地址以太坊、比特币等公链上的资产
  2. 攻击者地址可追踪部分约 1.41 亿美元
  3. USDT 换成 DAI避开发行方冻结
  4. 静置约两年2026 年 2 月起部分 ETH 进入 Tornado Cash

影响

SecurityWeek 当时称这是 2023 年已披露的最大一起盗币事件[5]。消息传出后，XIN 下跌约 8%，跌到 195 美元左右[2]。

争议的焦点是“去中心化”。Mixin 对外说资产存放在 PoS-BFT-DAG 分布式网络中[14]，出事的却是一个云服务商的数据库。共识层的去中心化和托管层的去中心化是两回事：前者决定账本会不会被篡改，后者决定公链上的钱会不会被转走。用户看到的“分布式网络”说的是前者，真正决定资金安全的是后者。

事发后有人猜测是朝鲜 Lazarus 所为。BleepingComputer 写道，没有证据指向 Lazarus，这起事件也没有被归因于它[4]。本站查到的资料里，没有执法机构或安全公司把它正式归因于某个团伙。

后续处置

赔付方案

赔付方案前后有两个说法。9 月 25 日的直播里，冯晓东说先赔付最多 50%，其余部分发放代币化的债权，由公司用未来利润回购[3][5]。两天后他公布了按币种区分的比例，并说正式公告还需要时间，但比例的浮动不会超过 1%[7]：

资产先行赔付缺口
BTC90%记为 MDTb
ETH30%记为 MDTe
ERC20-USDT10%记为 MDTu
其他链上的 USDT不受影响无
其他币种计划 100%无

赔付比例来自 TechFlow 2023-09-27 的报道[7]，债务代币的对应关系来自 Mixin 2024-01-31 的公告[8]。赔付按被盗时的价格折算成美元，资金来自 Mixin 已有的资金和借款[7]。

两个说法之间的关系，官方没有专门解释。可以看到的是，BTC 的比例高于 50%，ETH 和 ERC20-USDT 低于 50%。

债务代币与兑付进展

2024 年 1 月 31 日，Mixin 正式推出 MDT 债务代币，每枚价值 1 美元，用户通过迁移机器人领取[8]。Mixin 还承诺，如果在兑付完成前攻击者归还了被盗资产，持有 MDT 的用户可以换回原来损失的资产[10]。

2026 年 9 月 23 日，Mixin 宣布用经营利润完成了 MDTu 对应的 2,300 万美元全额兑付[10]。同年 2 月的报道写道，MDTb 和 MDTe 没有兑付时间表[9]；10 月的报道只提到 MDTu 已经完成[10]。Mixin 仍在运营，2026 年自称资产规模超过 10 亿美元[9][10]。

至今没有公开的内容
  • 事故报告：云服务商是谁、入侵路径、数据库里有什么、签名能力是怎样被拿到的。
  • 调查结论：Mixin 说已请 Google 和 SlowMist 协助调查[1]，结论没有发布。
  • 确认后的最终损失，以及 MDTb、MDTe 的发行规模和兑付计划。
  • 是否报警、是否有执法机构立案。

教训与防御

给钱包和托管服务
  • 签名材料不进通用数据库。私钥、加密后的私钥和解密它的密钥，不能放在一个能被整体拖走的地方。签名应在 HSM、MPC 节点或可信执行环境里完成，数据库被拖走也拿不到能签名的东西。
  • 设计文档里的安全措施要真的部署，并公开说明部署到了哪一步。写在 README 里的“尚未集成”，大多数用户不会去读。
  • 把云服务商当作信任链的一环。它的员工权限、日志保留和入侵检测，都属于你的威胁模型。
  • 外链资产的大部分放在需要多方签名的冷存储里，在线钱包设额度上限和异常出金告警。
  • 出事后发布技术复盘。不公开原因，别人就无法判断同样的问题是否已经修好。
给用户
  • 判断一个钱包是否安全，要问签名能力在谁手里、放在哪里，而不只是它用了什么共识算法。
  • “去中心化网络”可能只说明账本是分布式的，不代表托管也是。
