总览　/　2019 年　/　智能合约登场

币安被盗 7,074 枚 BTC

2019 年 5 月 7 日 17:15（UTC），币安的比特币热钱包在一笔提币交易中转出约 7,000 枚 BTC，按当时价格约 4,000 万美元。攻击者没有碰交易所的私钥，而是事先收集了大量用户的 API 密钥和二次验证码，再让多个看似无关的账户同时提币，每个请求都通过了风控。第二天赵长鹏在直播中说正在考虑重组比特币区块，遭到大量反对后放弃，损失由用户安全资产基金（SAFU）全额承担。

概要

这次被盗用的是用户的钥匙，不是交易所的。币安说，攻击者用钓鱼、病毒等多种手段拿到了大量用户的 API 密钥、二次验证（2FA）码和其他信息，然后耐心等待，在“最合适的时机”通过多个看似互不相关的账户同时发起提币。这些提币的组织方式通过了币安当时的全部安全检查，被合并进同一笔交易，从热钱包转了出去[1]。

这笔交易打包在区块 575,013，总额 7,074.19 BTC，共 44 个输出[2]。币安公布的被盗数量是 7,000 BTC，并说这个热钱包只存放了它约 2% 的比特币。交易执行后才触发告警，币安随即暂停了所有提币[1]。本站标题沿用的 7,074 BTC 是整笔交易的总额，其中包含同一批次里的其他输出。

此后一周，两件事引起了更多关注。一是赵长鹏在直播中谈到可以和矿工协调重组比特币区块，把被盗的币从攻击者手里拿走，比特币社区强烈反对，他当天宣布放弃[4]。二是币安动用 2018 年 7 月设立的 SAFU 基金赔付了全部损失，冻结所有旧 API 密钥，系统升级后在 5 月 15 日恢复充提[3][10]。攻击者身份至今没有公开。

背景

2019 年的币安是按交易量计算的全球最大加密资产交易所[5]。大量用户通过 API 密钥把账户接到量化程序和第三方交易工具上：程序拿着密钥和对应的密文签名请求，就能代替用户查余额、下单，如果用户开了提币权限，还能提币。

交易所自己的私钥分为冷钱包和热钱包。热钱包常驻在线，用于自动处理用户的提币请求；为了省手续费，交易所通常把一段时间内的多笔比特币提币合并成一笔交易发出，每个收款地址对应一个输出。只要提币请求来自真实账户并通过风控，热钱包就会为它签名。

2018 年 7 月起，币安每月把 10% 的交易手续费存入用户安全资产基金（Secure Asset Fund for Users，SAFU），专门用于极端情况下的赔付。据 CoinDesk 报道，2018 年 7 月到 2019 年 3 月币安的利润约 2.1 亿美元[4]。

攻击原理

热钱包的私钥没有泄露，比特币协议也没有漏洞。攻击者走的是交易所正常的提币流程：用被盗的凭据控制真实用户的账户，提交提币请求，等热钱包按规则签名。能不能拦住，取决于交易所在签名之前做了哪些检查。

凭据：API 密钥和 2FA 码

币安列出的被盗内容是“大量用户的 API 密钥、2FA 码，可能还有其他信息”，手段包括钓鱼、病毒和其他攻击[1]。开了提币权限的 API 密钥，单凭密钥就能发起提币。2FA 码是一次性的，几十秒内就会失效，攻击者能用上，通常说明他能在用户输入的同时截获，或者已经控制了用户的设备。事发第二天，币安以“部分 API 出现异常交易”为由，把所有现有 API 密钥降为只能交易，并在当天删除[7]，可见 API 密钥是被滥用的主要入口之一。

风控：逐个检查，没有合起来看

币安的说法是，攻击者“通过多个看似独立的账户”行动，交易的组织方式“通过了现有的安全检查”，执行之后才触发告警[1]。赵长鹏在直播中补充，攻击者拿到一个账户后并不马上动手，而是等手里有了大量高净值账户[4]。每个账户单独看都在正常范围内，异常只有合起来才看得出：同一时段、同一批次里，多个此前互不相关的账户同时把大额 BTC 提往新地址。币安没有公开风控规则的细节，下图按公告的描述绘制。

签名之后就没有回头路

交易所把一批提币合成一笔交易签名广播，几分钟内就会被打进区块。比特币没有冻结功能，也没有任何一方能撤销已确认的交易，所以交易所的全部防线都必须在签名之前。币安的告警是在交易执行之后才响起的，这时能做的只剩暂停后续提币[1]。

热钱包只放 2% 意味着什么

币安说被盗的热钱包只存放了它约 2% 的比特币，其他钱包没有受到影响[1]。热钱包的余额就是这类攻击的损失上限。攻击者能骗过风控，但只能拿走热钱包里已有的币。这次损失约 4,000 万美元而不是更多，靠的是这条上限，而不是风控。

攻击过程

币安没有发布完整的事后报告。下面的经过依据币安当时的公告、赵长鹏的直播和区块链公开记录。

  1. 收集凭据攻击者用钓鱼、病毒等多种手段，陆续拿到大量用户的 API 密钥、2FA 码和其他信息[1]。具体是哪些钓鱼页面、哪种恶意软件，币安没有公开。
  2. 等待和积累攻击者拿到账户后没有立即动手，而是等到手里有了大量高净值账户[4]。
  3. 同时提币5 月 7 日，多个看似独立的账户在“最合适的时机”同时发起提币，这些请求都通过了当时的安全检查[1]。
  4. 一笔交易转出热钱包把这批提币合并签名，交易在 17:17（UTC）被打包进区块 575,013[2]。交易执行后，系统告警，币安暂停了所有提币[1]。
  5. 余波币安提醒，攻击者可能仍然控制着部分用户账户，并可能借此影响价格；但提币关闭后，操纵价格已经没有多少动机[1]。

影响

重组比特币区块的提议

事发几小时后，参与过比特币和 Stellar 核心代码开发的 Jeremy Rubin 在推特上向赵长鹏提出：如果币安公开被盗币对应的私钥，就能“去中心化地、零成本地”协调一次重组来撤销这次盗窃[5]。具体做法是让多数矿工从被盗交易之前的区块重新出块，构造一笔交易把攻击者收到的币分给矿工，其他交易全部保留。赵长鹏后来澄清，这个方案不是回滚任何交易，也不是把钱还给币安[5]。

  1. 区块 575,013被盗交易已确认，币进入攻击者地址
  2. 提议多数矿工从此前的区块另起一条更长的链
  3. 新链保留其他交易，把攻击者收到的币分给矿工
  4. 结果赵长鹏 5 月 8 日宣布放弃

5 月 8 日 03:00（UTC）的 Periscope 直播中，赵长鹏说“说实话，我们大概几天内就能做到”，但这可能会“破坏比特币的信誉”，团队还在算账[4]。反对意见来得很快[5]：

  • 开发者 Udi Wertheimer 算了一笔账：挖一天的矿要 1,800 BTC，回滚四天的成本超过被盗金额本身。
  • 开发者 Jimmy Song 估算，要足以激励矿工改写历史，损失至少是 7,250 BTC。
  • 康奈尔大学的 Emin Gün Sirer 说，收买 51% 的矿工就能改账本，这说明工作量证明链的不可逆性有多弱。
  • 投资人 Michael Novogratz 说，谈论分叉或重组“近乎异端”；他说以太坊社区那样做时项目“像个婴儿”，而比特币已是市值千亿美元的价值储存手段。
  • Blockstream 的 Adam Back 说重组“不会发生”，并列出 2014 年 Mt.Gox、2016 年 Bitfinex 的更大损失作为对照。

当天赵长鹏发推宣布不采取重组方案，理由有四点：

1. 可能损害比特币的信誉。2. 可能导致比特币网络和社区分裂。3. 黑客确实暴露了我们设计中的某些弱点和此前不明显的用户困惑。4. 这是一次非常昂贵的教训，但仍是教训。

赵长鹏推文，2019-05-08，转引自 CoinDesk[5]

Multicoin Capital 的 Tushar Jain 则认为重组不应被一概否定，只是这次“时间过去太久了”。他的看法是，如果在 6 个区块内反应，或者交易还在内存池里时就用更高手续费发出一笔冲突交易，损失可以完全避免[8]。这场争论最后的结论很清楚：比特币社区不会为一家机构的损失改写账本，交易所的风险只能由交易所自己承担。与 The DAO 时的以太坊相比，比特币在这件事上的社会共识要坚决得多。

交易所的保险基金

币安在公告中第一时间承诺由 SAFU 全额承担损失，“用户资金不会受到影响”[1]。SAFU 按交易手续费的固定比例持续积累，这次约 4,000 万美元的损失全部由它承担。2020 年 KuCoin 被盗时，也是先承诺由交易所和保险基金兜底，再去追回资产。

后续处置

暂停充提与安全审查

币安在公告中说安全审查将覆盖“全部系统和数据”，预计需要一周，期间充提必须暂停，交易保持开放，方便用户调整仓位[1]。5 月 8 日，所有旧 API 密钥被降为只能交易，并在 13:30（UTC）全部删除，用户需要重新创建[7]。5 月 13 日，赵长鹏说系统已做了“大量重大改造”，许多高级安全功能是新加的或完全重新设计的，细节以后公布[9]。

5 月 15 日 03:00（UTC）开始的系统升级比预计多用了 2 小时[10][11]。升级完成后，交易在 13:00 恢复，充值先行开放，提币在交易恢复后不久开放。公告建议用户修改密码、重置 2FA、更新防钓鱼码，同时推出了 50,000 BNB 的交易抽奖和 VIP 等级临时提升[3]。从暂停提币到恢复，共约 8 天。

赔付

损失全部由 SAFU 承担，币安称没有用户资金受到影响[1]。赵长鹏在直播中说这笔损失“确实很痛”[4]。

没有公开的部分

赵长鹏曾说恢复运营后会发布更详细的说明[9]。本站没有找到这份报告，也没有找到关于攻击者身份、被盗 BTC 后续流向或执法进展的公开信息。哪些用户的凭据被盗、通过哪些钓鱼页面或恶意软件被盗、风控具体改了什么，都没有公开。

教训与防御

给交易所
  • 风控要在批次和时间窗口上做聚合：同一时段内多个账户同时向新地址大额提币，即使每个请求单独看都正常，也应整批暂停复核。
  • API 密钥默认不带提币权限；开启提币权限时强制绑定 IP 白名单，提币地址走白名单并设置冷却期。
  • 热钱包余额决定这类攻击的损失上限，按“一个批次最多可能被骗走多少”来设定热钱包的规模。
  • 告警必须在签名之前触发。签名广播之后，比特币上没有任何撤回手段。
给用户
  • 给交易机器人用的 API 密钥只开交易权限，并限制来源 IP。不要把带提币权限的密钥交给任何第三方工具。
  • 一次性验证码可以被钓鱼页面实时转发。能用硬件安全密钥（FIDO2/U2F）的地方就不用验证码。
给协议和社区
  • 这场争论确认了一条边界：比特币不会为单一机构的损失重组区块。交易所只能把风险留在自己的系统里，用余额上限、风控和保险基金承担。
